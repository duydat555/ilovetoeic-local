# Arena audit — 2026-10-22

## Confirmed defects and fixes

- Display settings did not scale Arena text: CSS used pixel sizes and a hardcoded font. Arena now uses rem sizes, the shared font family and body weight variables. Headings retain the application's shared heading policy. The audit reproduces the original failure (12px stayed 12px at scale 125) and verifies the real settings service now changes text size by the configured 1.3 ratio.
- Large scale and long names/questions could squeeze columns or overflow. Container queries collapse columns based on available space; controls wrap, answer columns can shrink, and long unbroken text wraps. Mobile inputs retain a minimum 16px font to avoid focus zoom on iOS.
- Arena's layout used a fixed viewport height. Its shell now uses dynamic viewport height and a bounded, shrinkable scrolling main area. The full-bleed winter background is preserved. Dialog and leaderboard scroll areas contain overscroll.
- Ready was actionable while searching although the server cannot mark that state ready. It is now disabled until an opponent has joined.
- Copy room code had no success feedback and silently did nothing when the Clipboard API was unavailable. It now announces success or displays the code with a fallback explanation.
- Mutation actions now have a synchronous in-flight guard, covering repeated clicks before React renders the disabled button.

## Verification

- `npm run build`: passed, exit code 0. Existing bundle size advisory remains. An earlier PowerShell-captured build hit a Node/Windows shutdown assertion after producing artifacts; a final normal build under cmd completed cleanly.
- Scoped ESLint checks: passed on all five Arena TypeScript/TSX files (unused variables, explicit any, unreachable code, constant conditions). This is not a whole-repository lint pass.
- `client/tests/arena.audit.mjs`: passed using browser fixtures; no real API or database writes. It applies settings through `displaySettings.ts`, checks font/weight/scale, scroll access and horizontal overflow at 20 viewport/scale combinations (320, 390, 768, 1366, 1920px × 90, 100, 110, 125), long history modal scrolling/focus/Escape, searching readiness, clipboard feedback, and long gameplay text at 125%. No browser errors.
- `client/tests/arena.browser.mjs`: passed with two authenticated browsers against the actual app and a disposable MySQL fixture. All three modes completed (7/10/5 rounds), XP and ledger/history agree, reconnect/reload resume the same match, and private-room cancellation refunds. The browser test now explicitly routes loopback API traffic to the disposable service on port 8009, regardless of the frontend build API default.
- `server/tests/test_arena.py`: all 13 tests passed against disposable loopback databases. The actual FastAPI app also started successfully in the browser harness.
- `client/tests/arena.presentation.mjs`: passed on the final build. Five viewport sizes retain an edge-to-edge background; snow animates and respects reduced motion; audio produces a measurable signal after a gesture, mute persists, state transitions play cues once, and leaving Arena closes the audio context.

Evidence is recorded in `screenshots/audit-2026-10-22/`. Screenshots use synthetic fixture data. Layout was inspected in desktop Chrome with emulated viewport sizes; physical iOS/Android browser testing is not claimed.

After validation, the owned preview and test API processes were stopped. The leftover browser-fixture database was checked for exactly four fixture users and the fixture test bank, then removed. No production deployment or production-data changes were performed for this audit.
